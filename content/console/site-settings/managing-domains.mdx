---
title: 'Managing Domains'
description: 'How to add a domain in Blutui, connect it to a project, verify it with DNS records and make your site live.'
---

To serve a site on your own domain, add the domain in Blutui, attach it to a project, add the DNS records at your DNS provider and verify the domain. Once it is verified and the project is published, visitors can reach the site on that domain.

## Configure a domain

<Steps>
<Step>
### Add the domain in Blutui

1. In the Console, open your agency and go to **Domains**.
2. Click **Add domain**.
3. Under **Domain name**, type the domain without `https://` or a trailing slash, for example `example.com`.
4. Click **Add domain**.

This takes you to the domain's page, which shows a **Verification pending** banner.
</Step>

<Step>
### Attach it to a project

1. On the domain's page, find the **Project** box.
2. Open the dropdown, search for the project and select it.
3. Click **Confirm change** in the dialog that appears.
</Step>

<Step>
### Add the DNS records at your provider

The **DNS records** table at the bottom of the domain's page shows the exact values for this domain.

<Callout type="warn">
Copy the records from the DNS records table rather than from these instructions. The TXT record is unique to each domain.
</Callout>

For a root domain (`example.com`), add:

| Type | Name / Host | Value | TTL |
| --- | --- | --- | --- |
| `A` | `@` | `75.2.24.109` | `3600` |
| `TXT` | The domain's ID, a long code shown in the table | `blutui_verification=…`, shown in the table | `3600` |

For a subdomain (`www.example.com`, `shop.example.com`), the table shows a CNAME record instead of an A record:

| Type | Name / Host | Value |
| --- | --- | --- |
| `CNAME` | The subdomain, for example `www` | `projects.blutui.com` |
| `TXT` | `<domain ID>.www` | `blutui_verification=…` |

At your DNS provider (GoDaddy, Cloudflare, Namecheap, etc.):

1. Open the DNS settings for the domain.
2. Delete any existing `A` and `AAAA` records on `@` (or on the subdomain, if you're connecting one) that point somewhere else. The A record is checked against Blutui's IP addresses, and any other records left there will still send some visitors to the old site.
3. Add the A record (or the CNAME record for a subdomain) and the TXT record exactly as the table shows them.
4. Check the **Host** field. Most providers add your domain to the end automatically, so enter only the ID (or `ID.www`), not `ID.example.com`. If your provider shows the full name after you save and it ends up as `ID.example.com.example.com`, remove the duplicated part.

<Callout>
If you use Cloudflare, set the A or CNAME record to **DNS only** (grey cloud). If it's proxied (orange cloud), Cloudflare hides Blutui's IP address and the check will fail.
</Callout>
</Step>

<Step>
### Verify the domain

Blutui checks pending domains automatically every 2 minutes. To check straight away, click **Check DNS records** on the domain's page.

If the check fails, the message tells you which record is missing:

- **A or CNAME record not configured**: the A or CNAME record is missing, hasn't spread across the internet yet, or points to the wrong place.
- **TXT verification record not found**: the TXT record is missing, or its host or value is wrong.

DNS changes usually take effect within minutes but can take up to 72 hours. Once the check passes, the domain shows as verified.
</Step>

<Step>
### Make the site live

The project must be [published](/console/site-settings/publishing) for the domain to serve the site.

If the project has more than one domain, choose which one is the primary domain in the project's own domain settings.
</Step>
</Steps>

## Primary and connected domains

When your site is published, it is served from its primary domain. Any other domains connected to the project automatically redirect to the primary domain. You can change the primary domain at any time in the project's domain settings. Only verified domains can be used.

## SSL/TLS certificates

Every domain needs an SSL/TLS certificate, which encrypts traffic between visitors and your site and confirms the site's identity. You can request a certificate for a domain from the project's domain settings.
